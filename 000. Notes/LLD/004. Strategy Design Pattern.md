# Strategy Design Pattern: Walkable, Flyable, & Talkable

## 📌 Identifying the Problem
* Applications frequently change, and hardcoding behaviors directly into classes leads to rigid, duplicated code.
* If we have a parent class with multiple child classes, placing methods like `fly()` or `talk()` in the parent forces all children to inherit them, even if those specific children cannot fly or talk.
* Using simple interfaces (e.g., `IFlyable`) forces every individual child class to implement the exact same flying logic from scratch, leading to massive code duplication across the system.

## 💡 The Strategy Solution
* **Encapsulate what varies:** Extract the changing behaviors (`Walkable`, `Flyable`, `Talkable`) out of the main entity and into their own distinct strategy classes.
* **Favor Composition over Inheritance:** Instead of the main object inheriting behaviors, it *contains* a behavior object (a "Has-A" relationship).
* **Runtime Flexibility:** You can swap an object's behavior dynamically at runtime without altering its underlying code.

## 🛠️ Java Implementation: The Video Example

```java
// 1. Create Strategy Interfaces
interface FlyStrategy { void fly(); }
interface WalkStrategy { void walk(); }
interface TalkStrategy { void talk(); }

// 2. Concrete Strategy Implementations
class CanFly implements FlyStrategy {
    public void fly() { System.out.println("Flying high in the sky!"); }
}
class CannotFly implements FlyStrategy {
    public void fly() { System.out.println("I cannot fly."); }
}

class FastWalk implements WalkStrategy {
    public void walk() { System.out.println("Walking very fast!"); }
}

// 3. The Context Class (Uses Composition)
class Character {
    private FlyStrategy flyStrategy;
    private WalkStrategy walkStrategy;

    // The strategy is injected via the constructor
    public Character(FlyStrategy flyStrategy, WalkStrategy walkStrategy) {
        this.flyStrategy = flyStrategy;
        this.walkStrategy = walkStrategy;
    }

    public void performFly() { flyStrategy.fly(); }
    public void performWalk() { walkStrategy.walk(); }
    
    // Allows changing the strategy at runtime
    public void setFlyStrategy(FlyStrategy flyStrategy) {
        this.flyStrategy = flyStrategy;
    }
}

// 4. Client Code
public class Main {
    public static void main(String[] args) {
        // Create a character that can fly and walk fast
        Character hero = new Character(new CanFly(), new FastWalk());
        hero.performFly();
        
        // Dynamically change behavior at runtime without changing the Character class
        hero.setFlyStrategy(new CannotFly());
        hero.performFly();
    }
}
