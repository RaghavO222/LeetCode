# UML Diagrams: Class & Sequence Diagrams
*Based on the video by Coder Army*

## 📌 Introduction to UML Diagrams
UML (Unified Modeling Language) diagrams are an intuitive way to visually represent the architecture, components, and flow of an application. Instead of writing long, monotonous paragraphs to explain an idea, UML diagrams help map out components and how they interact.

In Low-Level Design (LLD), there are **14 total UML diagrams**, but they are broadly classified into two categories:
1. **Structural Diagrams (Static):** Shows the static architecture (what components exist and how they are connected). *Example: Class Diagram.*
2. **Behavioral Diagrams (Dynamic):** Shows the interaction and flow between components over time. *Example: Sequence Diagram.*

---

## 1️⃣ Class Diagrams
Class diagrams show the classes in your application and the associations (relationships) between them. 

### Structure of a Class
A class is represented by a rectangle divided into three horizontal compartments:
* **Top Compartment:** Class Name. (If it is an abstract class, the word "Abstract" is written above it).
* **Middle Compartment:** Characteristics/Variables (Attributes).
* **Bottom Compartment:** Behaviors/Methods (Functions).

### Access Modifiers
To represent data security (Encapsulation), specific symbols are used before variables and methods:
* `+` **Public:** Can be accessed from anywhere.
* `#` **Protected:** Can be accessed within the class and its child classes.
* `-` **Private:** Can only be accessed strictly within the class.

### Associations & Relationships
Associations define how classes interact and depend on each other. 

**1. Class Level Association (Inheritance / "Is-a" relationship)**
* **Meaning:** Represents parent-child relationships (e.g., A *Cow is an Animal* or *Manual Car is a Car*).
* **Representation:** A solid line with a **closed hollow arrow** pointing toward the Parent class.

**2. Object Level Association ("Has-a" relationship / Composition)**
Divided into three types based on the strength of the bond:
* **Simple Association:** The weakest link. The objects are related, but independently exist. 
    * *Example:* Arjun lives in a House (Arjun *has a* House).
    * *Representation:* A solid line with an **open arrow**.
* **Aggregation:** A container relationship where parts **can** exist independently of the parent. 
    * *Example:* A Room has a Sofa, Bed, and Chair. If the room is destroyed, the sofa/bed still exists physically.
    * *Representation:* A solid line with a **hollow diamond** pointing towards the container (Room).
* **Composition:** The strongest bond where parts **cannot** exist independently of the container. 
    * *Example:* A Chair has Wheels, Arms, and a Seat. The wheels and arms don't represent anything without the chair structure.
    * *Representation:* A solid line with a **filled (solid) diamond** pointing towards the container.

*(Note: Programmatically, these "Has-a" relationships are all implemented by passing an instance reference of one class inside another).*

## 2️⃣ Sequence Diagrams
Sequence diagrams show how objects (A, B, C) interact with each other over time in a specific use-case (e.g., a user withdrawing cash from an ATM).

### Key Components:
* **Object:** Represented as a rectangle at the top. Internal class structures are ignored here.
* **Lifeline:** A vertical dashed line dropping from the object showing its existence span during the application's runtime.
* **Activation Bar:** A thick vertical rectangular box on the lifeline that shows exactly when the object is active (sending/receiving messages). 

### Types of Messages:
* **Synchronous Message:** Sender sends a message and waits for a response. Represented by a solid line with a **closed arrow**. The response comes back as a **dashed line**.
* **Asynchronous Message:** Sender sends a message and moves on without waiting for a reply. Represented by a solid line with an **open arrow**.
* **Create Message:** A message that spins up a completely new object (creating a new lifeline).
* **Destroy Message:** A message that ends an object's lifeline, freeing it from memory.
* **Lost Message:** A message sent but didn't reach the target (e.g., target's activation bar ended). Represented with a circle/dot at the arrow tip.
* **Found Message:** A message received from an unknown or already deactivated source.

### Conditional Blocks:
If you need to show programming logic inside the sequence flow:
* **Alt:** Represents an *If-Else* block (e.g., Alt: Balance sufficient -> Dispense cash. Else -> Return Error).
* **Opt:** Represents a simple *If* condition.
* **Loop:** Represents *iterations/loops*.

**General Tip:** You don't build one sequence diagram for the whole app. You build one for every specific user flow (like ATM Withdrawal, ATM Pin Change, etc.).
